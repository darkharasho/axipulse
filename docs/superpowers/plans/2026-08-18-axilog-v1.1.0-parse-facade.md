# axilog v1.1.0 — Parse Facade and Received-Healing Series

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship axilog v1.1.0 with a single shared `parse_report_v1` entry point and the incoming healing/barrier per-second series, so both AxiPulse repos can migrate onto the native format.

**Architecture:** A new thin `axilog-api` crate owns the ~90-line orchestration currently duplicated in `axilog-node` and `axilog-cli`; both are refactored onto it. Separately, `healing_detail.rs` gains receiver-indexed accumulators mirroring its existing healer-indexed `healing_1s`, surfaced on `blocks.series.by_entity[].{healing_received_1s,barrier_received_1s}`.

**Tech Stack:** Rust 2021 (rust-version 1.74), cargo workspace, napi-rs, serde/serde_json.

**Spec:** `docs/superpowers/specs/2026-08-18-axilog-migration-design.md` (in the `axipulse` repo, Part 0)

**Repo:** `axilog` (`../axilog` relative to axipulse) — **all work in this plan happens there.**

## Global Constraints

- Workspace version moves `1.0.0` → `1.1.0`; edition 2021; rust-version 1.74; MIT.
- `axilog-core` must NOT depend on `axilog-schema` — `axilog-schema` already depends on `axilog-core`, so that is a cargo cycle.
- `axilog-api` re-exports `axilog_schema::v1` so a consumer declares one dependency.
- `ParseOpts.everything` is a **union** with the individual flags, never an override.
- ei-json output must be **byte-identical** before and after the refactor on the committed fixture — axibridge consumes it exclusively.
- The new series ride the existing `timeseries` gate. No new gate.
- `healing_received_1s` / `barrier_received_1s` must use the same `ei_grid`/`ei_bucket` helpers as `healing_1s`, so the grids cannot diverge.
- Run tests with `cargo test --workspace`.

    pub missiles: bool,
    pub rotation: bool,
    pub modifiers: bool,

    let o = match o { Some(o) => o, None => return Default::default() };
    axilog_api::ParseOpts {

        skill_damage: o.skill_damage.unwrap_or(false),

        missiles: o.missiles.unwrap_or(false),
        rotation: o.rotation.unwrap_or(false),
        modifiers: o.modifiers.unwrap_or(false),
        everything: o.everything.unwrap_or(false),

/// Incoming is the transpose of outgoing: every healing amount that
/// lands on an ally must appear in that ALLY's received series, on the
/// same grid, cumulative in the same way.
#[test]
fn received_series_is_the_transpose_of_outgoing() {
    let d = build_test_detail(); // the existing helper used by the tests above
    let buckets = d[0].healing_1s.len();
    for p in &d {
        assert_eq!(p.healing_received_1s.len(), buckets, "same grid as healing_1s");
        assert_eq!(p.barrier_received_1s.len(), buckets, "same grid as healing_1s");
        // Cumulative fill-forward is monotonic.
        assert!(p.healing_received_1s.windows(2).all(|w| w[1] >= w[0]));
        assert!(p.barrier_received_1s.windows(2).all(|w| w[1] >= w[0]));

fn received_series_ride_the_timeseries_gate() {

    let mut checked = 0;

            let h = e.healing_received_1s.as_ref().unwrap();
            assert_eq!(h.len, e.healing_1s.as_ref().unwrap().len, "same grid length");
            assert_eq!(h.interval_ms, 1000);
            checked += 1;
        }
    }
